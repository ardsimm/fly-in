# Parse errors: no line numbers, several messages do not name the line

## Summary

VII.4: "Any other parsing error must stop the program and return a clear error message
indicating the line and cause." Every malformed map is rejected (behaviour is correct), but no
message has a line number and about half do not quote the offending line. Some have typos.
Found during the audit in `claude/reports/report_3_20260929-041535.md` (section 6.5). This
supersedes item 10 of issue_0.

## Messages

| Input | Message | Problem |
|---|---|---|
| `max_drones=0` | `Invalid max drones 0:max_drones must be am integer >= 1` | no line, "am", missing space (`parser.py:197`) |
| `[speed=9]` | `Parsing error: invalid metadata: [speed=9]` | no line |
| `hub: a 1.5 0` | `invalid value: 1.5 for hub coordinate` | no line, does not say x or y |
| `hub: a-b 1 0` | `Invalid name a-b:names cannot contain ...` | no line, missing space |
| `connection: a-a` | `This implementation does not accept self-loops (a-a)` | no line |
| second `start_hub` | `File must only contain one start_hub` | no line |
| second `nb_drones` | `File has > 1 nb_drones lines` | no line |
| duplicate metadata key | `Error in line "max_drones=1 max_drones=5"` | quotes the metadata, not the line |
| `hubb: a 1 0` | `Invalid line prefix "fhubb"` | stray `f`: `\"f{` inside an f-string (`parser.py:592`) |
| line without `:` | `An unhandled error occured while parsingline: "...": substring not found` | `line.index(':')` raises; missing space; "unhandled" wording |
| `connection:` (empty) | `Invalid line prefix "fconnection"` | wrong cause |
| UTF-8 BOM before `nb_drones` | `First line must be nb_drones` | confusing; strip `﻿` |
| `nb_drones:5`, `hub:a 1 0` | `First line must be nb_drones` / `Invalid line prefix "fhub"` | should say a space is expected after `:` |

Minor, accepted silently: `[zone=]` (normal), `[color=]` (none), `1_000` and `+3` as integers.

## Suggested approach

`__strip_lines` drops blank and comment lines, which loses the original numbering. Keep
`(line_number, text)` pairs, and wrap the per-line parsing so that every `ParsingError`
raised inside is re-raised as `Line N: "<original line>": <cause>`. Then the individual raise
sites only need to describe the cause.

## Checklist

- [ ] Prefix every per-line error with the line number and the original line
- [ ] Global errors (missing start/end, no connections) say so without a line
- [ ] Fix the stray `f` in the prefix message and the "am" typo
- [ ] Handle lines without `:` explicitly
- [ ] Coordinate error names x or y
- [ ] (Optional) Strip a UTF-8 BOM; reject empty metadata values
