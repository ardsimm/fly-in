# The code does not run on Python 3.10 or 3.11

## Summary

The subject requires "Python 3.10 or later", and `pyproject.toml` declares
`requires-python = ">=3.10"`. The code only runs on 3.12+. Found during the audit in
`claude/reports/report_3_20260929-041535.md` (section 6.2).

## Details

Checked with `/usr/bin/python3.10` (3.10.12), parsing each file with `ast.parse`:

| File | Construct | Needs |
|---|---|---|
| `src/parser/parser.py:1` | `from enum import StrEnum` | 3.11 |
| `src/models/node.py:46` | f-string replacement field spanning several lines | 3.12 (PEP 701) |
| `src/parser/parser.py:440`, `:592` | same | 3.12 |
| `src/simulation/simulation.py:360`, `:373`, `:381`, `:388` | same | 3.12 |
| `src/visualiser/elements/node_element.py:119` | same | 3.12 |

Result on 3.10: four modules fail with `SyntaxError: unterminated string literal`, and the
`StrEnum` import fails. On 3.11 the f-strings still fail.

Also, `typing_extensions` is imported in 8 files (`override`, `final`, `TypedDict`,
`Literal`) but is not a declared dependency. It is only present because mypy/pydantic pull it
in. `typing.TypedDict` and `typing.Literal` exist since 3.8; `override` needs 3.12 in
`typing`.

## Options

- Keep 3.12 features and declare `requires-python = ">=3.12"`. This still satisfies "3.10 or
  later", and it is one line. Be ready to justify it at evaluation.
- Or make the code 3.10-compatible: rewrite the 8 f-strings on one line (or with an
  intermediate variable), replace `StrEnum` with `str, Enum`, and add `typing-extensions` to
  the dependencies.
