# Output format does not match VII.5

## Summary

The printed schedule is the graded artefact (turn count, validity). It deviates from the
subject's format in four ways. Found during the audit in
`claude/reports/report_3_20260929-041535.md` (section 6.3).

## Current output (HEAD, `easy/01_linear_path.txt`)

```
pygame-ce 2.5.8 (SDL 2.32.10, Python 3.12.13)
D0-start D1-start
D0-waypoint1
D0-waypoint2 D1-waypoint1
D0-goal D1-waypoint2
D1-goal
```

## Expected

```
D1-waypoint1
D1-waypoint2 D2-waypoint1
D1-goal D2-waypoint2
D2-goal
```

## Details

1. **Initial line.** `get_turns` treats the first path element (every drone in the start zone)
   as a move, so HEAD prints `D0-start D1-start ...` as turn 1. It adds one turn to every
   count; on `medium/02_circular_loop` that is 16 against a target of 15. The uncommitted
   `turns[1:]` in `print_turns` fixes the printing; it is cleaner to not emit the move in
   `get_turns` at all, so the turn list and the printed lines agree.
2. **0-based IDs.** `Drone.__str__` (`src/models/drone.py:26-27`) returns `f"D{self.id}"`, and
   ids are `range(nb_drones)` (`parser.py:618`). The subject's IDs are `D1, D2, ...`. The
   `Drone.name` field already holds `D1`, and is unused.
3. **pygame banner on stdout.** pygame-ce prints its version line when imported. Set
   `os.environ["PYGAME_HIDE_SUPPORT_PROMPT"] = "1"` before the first `import pygame`.
4. **Trailing space** on every line (`print(..., end=" ")` in `simulation.py:403`). Use
   `" ".join(...)`.

Also: "Failed to find solution" is printed to stdout, mixed with the schedule. Error messages
belong on stderr.

Optional, suggested by VII.6: print the total number of turns and secondary metrics (average
turns per drone, total path cost) to stderr or after the schedule, so peers can compare
without counting lines.

## Checklist

- [ ] Hide the pygame support prompt
- [ ] Remove the trailing space
