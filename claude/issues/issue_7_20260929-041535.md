# Visualiser: missing colors and missing information on screen

## Summary

The visualiser works on every provided map (step forward/back, auto-play, speed, reset,
hover labels). VII.6 scores "quality and usefulness of visual representation", and VI says
"When colors are specified, the implementation should provide visual feedback". These gaps
would be noticed. The two visualiser crashes are in issue_1. Found during the audit in
`claude/reports/report_3_20260929-041535.md` (section 6.7).

## Details

- **Colors.** `gray` and `darkred`, used in the provided maps, are not in
  `data/colors.json`, so those zones are drawn black. Lookup is case-sensitive, with no
  fallback to pygame's own named colors (`pygame.Color("gray")` works). `rainbow` (challenger
  map) is also missing, which is expected.
- **Connection colors** depend only on `connection.nodes[1]` (`connection_element.py:62-83`),
  so `a-r` and `r-a` look different. The zone type (restricted, priority, blocked) is never
  shown on the node itself.
- **No drone identification**: every drone is the same grey circle; no ID label, no
  highlight of a drone in flight on a restricted connection.
- **No turn counter** and no total; no on-screen help for the keys (arrows, space, up/down,
  r, q).
- **Scale**: one coordinate unit is one cell. `max_x = 100` gives 8 px cells and 2 px nodes.
- **Performance**: a new `pygame.font.Font` is created for every node and connection on every
  frame; create fonts once.
- **Zone occupancy** is not shown (e.g. `2/3` on a node), although capacities are.

## Checklist

- [ ] Fall back to `pygame.Color(name)` when a name is not in `colors.json`, case-insensitive
- [ ] Show zone type on nodes; color connections independently of their written order
- [ ] Label drones with their ID
- [ ] Show the current turn / total turns and a key legend
- [ ] Show current occupancy against capacity on zones (optional)
- [ ] Scale to the map's bounding box with a minimum node size
- [ ] Cache fonts
